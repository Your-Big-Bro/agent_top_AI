# MCP Experiment Lab

В данной работе студенты исследуют возможности **MCP сервера (Model Context Protocol)** на основе библиотеки `FastMCP`.

Цель — понять, как работают основные компоненты MCP:

- **Prompt** — шаблоны инструкций для LLM
- **Tool** — функции, которые модель может вызывать
- **Resource** — внешние текстовые данные
- **Transport протоколы** — способы взаимодействия клиента и сервера


## Установка зависимостей

Перед началом работы установите все необходимые зависимости:

```bash
make setup
```

## Запуск MCP сервера STDIO

Для запуска MCP сервера в режиме STDIO используйте команду:

```bash
make mcp_stdio
```

## Запуск MCP сервера Streamable HTTP

Для запуска MCP сервера в режиме Streamable HTTP необходимо выполнить две команды в разных терминалах.

## Запуск агента с MCP (stdio)

```bash
make agent
```

### Терминал 1: Запуск MCP сервера

```bash
make mcp
```

### Терминал 2: Запуск MCP Inspector

```bash
make inspector
```

### Добавление своего MCP сервера в Inspector

Inspector по умолчанию показывает только примеры серверов. Свой сервер нужно добавить вручную.

1. В файле `.env` должно быть `IS_STDIO = 'False'`, иначе `make mcp` запустит сервер в режиме stdio.
2. Перезапустите `make mcp` и убедитесь, что в логе есть `http://127.0.0.1:8000`.
3. В браузере нажмите **Add Servers** и заполните форму:

| Поле | Что вписать |
|------|-------------|
| Server ID | `my-server` (любое имя из латинских букв, цифр, `-` и `_`) |
| Transport | `streamable-http` |
| URL | `http://127.0.0.1:8000/mcp` |

4. Нажмите **Add**, затем включите переключатель на карточке `my-server`. Статус должен смениться на **Connected**, и появятся вкладки Tools, Prompts и Resources.

> Если в логе сервера указан другой порт, подставьте его в URL вместо `8000`.

## 4. Эксперименты с transport протоколами

Сервер может работать в двух режимах:

- `stdio`
- `streamable-http`

### 5. Заполните таблицу:

| Критерий | stdio | streamable-http |
|--------|--------|--------|
| способ соединения | стандартные потоки ввода и вывода процесса | HTTP-запросы с потоковым ответом |
| где используется | локальный запуск, CLI-клиенты, агент на той же машине | удаленный сервер, несколько клиентов |
| масштабируемость | один клиент на один процесс | много клиентов, горизонтальное масштабирование |
| задержка | минимальная, нет сети | выше из-за HTTP: 10.5 мс на вызов `add` |

## Краткие результаты

1. Prompt. Простая и сложная тема дают одну структуру. Пустая тема не вызывает ошибку. Неверный `level` дает стиль `beginner`. Правка текста меняет ответ модели.
2. Resources. Правка `.md` меняет ответ агента без правки кода.
3. Tools. Строки и дробные числа для `add` дают ошибку проверки схемы. `get_weather` не зависит от регистра. Неизвестный город дает понятный ответ.
4. Transport. `streamable-http`: подключение 253.4 мс, средний вызов 10.5 мс.
5. Таблица транспортов заполнена в разделе 5.
6. Сервер расширен новым tool, новым resource и обработкой ошибок.
7. Ответы на четыре вопроса даны в `REPORT.md`.
8. Агент вызывает инструменты, использует ресурсы и блокирует опасный запрос. Таблица 8.5 заполнена.

1. Ключ `OPENROUTER_API_KEY` не задан. Агент работал на демо-модели. С ключом агент работает на `ChatOpenAI` без правки кода.
