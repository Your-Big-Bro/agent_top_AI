# MCP Experiment Lab

В данной работе студенты исследуют возможности **MCP сервера (Model Context Protocol)** на основе библиотеки `FastMCP`.

Цель — понять, как работают основные компоненты MCP:

- **Prompt** — шаблоны инструкций для LLM
- **Tool** — функции, которые модель может вызывать
- **Resource** — внешние текстовые данные
- **Transport протоколы** — способы взаимодействия клиента и сервера


## Установка зависимостей

Перед началом работы установите все необходимые зависимости:

```bash
make setup
```

## Запуск MCP сервера STDIO

Для запуска MCP сервера в режиме STDIO используйте команду:

```bash
make mcp_stdio
```

## Запуск MCP сервера Streamable HTTP

Для запуска MCP сервера в режиме Streamable HTTP необходимо выполнить две команды в разных терминалах.

## Запуск агента с MCP (stdio)

```bash
make agent
```

### Терминал 1: Запуск MCP сервера

```bash
make mcp
```

### Терминал 2: Запуск MCP Inspector

```bash
make inspector
```

### Добавление своего MCP сервера в Inspector

Inspector по умолчанию показывает только примеры серверов. Свой сервер нужно добавить вручную.

1. В файле `.env` должно быть `IS_STDIO = 'False'`, иначе `make mcp` запустит сервер в режиме stdio.
2. Перезапустите `make mcp` и убедитесь, что в логе есть `http://127.0.0.1:8000`.
3. В браузере нажмите **Add Servers** и заполните форму:

| Поле | Что вписать |
|------|-------------|
| Server ID | `my-server` (любое имя из латинских букв, цифр, `-` и `_`) |
| Transport | `streamable-http` |
| URL | `http://127.0.0.1:8000/mcp` |

4. Нажмите **Add**, затем включите переключатель на карточке `my-server`. Статус должен смениться на **Connected**, и появятся вкладки Tools, Prompts и Resources.

> Если в логе сервера указан другой порт, подставьте его в URL вместо `8000`.

## Задание 7. Анализ: ответы

1. Чем отличаются prompt, tool и resource?

Prompt - это шаблон запроса к модели. Сервер отдает текст, модель использует его как инструкцию.
Tool - это функция с типизированными аргументами. Модель вызывает ее, сервер возвращает результат.
Resource - это внешние данные только для чтения. Клиент читает их сам и вставляет в контекст.

2. Когда что использовать?

Prompt используют для повторяемых инструкций и версий промпта. Tool используют для действий:
расчет, запрос к API, запись данных. Resource используют для справочных данных: документы, справки,
шаблоны писем.

3. Чем отличаются stdio и streamable-http?

stdio работает через потоки процесса. Это просто и быстро. Но клиент и сервер на одной машине.
streamable-http работает по сети. Один сервер обслуживает много клиентов. Нужен порт и сеть.

4. Какие преимущества MCP по сравнению с обычным API?

MCP описывает инструменты, промпты и ресурсы в одном протоколе. Клиент сам узнает схему инструментов.
Один сервер работает с разными клиентами и моделями. Меняется сервер, а не код агента.
Есть готовые SDK и инспектор для отладки.

## Какие ошибки обработали и как

1. Пустой текст и текст из пробелов: tool возвращает сообщение `Ошибка: текст пустой`. Проверка `text.strip()` не дает делить пустую строку.
2. Не строковый ввод: схема MCP отклоняет вызов до запуска кода. Клиент получает `ToolError` с текстом проверки.
3. Слишком длинный текст: лимит 10 000 символов. Tool возвращает `Ошибка: текст слишком длинный` и не тратит память на подсчет.
4. Файл ресурса не найден или недоступен: `_read_data` ловит `FileNotFoundError` и `OSError` и возвращает текст ошибки вместо падения сервера.


Для `stdio`: `make mcp_stdio` и `make agent`.
